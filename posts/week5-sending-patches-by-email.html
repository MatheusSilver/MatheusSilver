Sending patches by email with Git

Objective

Considering that patches for Linux are submitted through a list of email. This week, we configured our git to be prepared to create, and submit patches using our email as the sender.

Challenges

Initially, I tried to configure my Outlook client as the sender, despite the tutorial's original recommendation to use Gmail. One of the main challenges I faced was the recent requirement for 2-factor authentication (2FA), which meant I needed to configure an "App Password" within Outlook.

However, this feature was not available for my account. Because of that, I made a second attempt using my USP email, but I encountered the same requirement for an App Password, which was also unavailable on that account.

Finally, I followed the approach suggested by the tutorial's authors and used a standard Gmail account. This time, the process went smoothly, and I was able to complete the setup.

Experience

To be perfectly honest, I take pride in avoiding the command line whenever possible. However, after this week's experience, I am slightly more inclined to agree that using Git via the command line is considerably more practical and efficient than using the VS Code UI.

Even so, I will continue to avoid the command line where I can, simply because finding workarounds is more amusing and challenging : D
