Sending Patches by email with Git and USP Email

Objective

Considering that patches for Linux are submitted through an email mailing list, we configured our Git setup this week to create and submit patches using our personal email as the sender.

Challenges (Before 25/03)

Initially, I tried to configure my Outlook client as the sender, despite the tutorial's original recommendation to use Gmail. One of the main challenges I faced was the recent requirement for two-factor authentication (2FA), which meant I needed to configure an "App Password" within Outlook.

However, this feature was unavailable for my account. Consequently, I made a second attempt using my USP email, but I encountered the same requirement for an App Password, which was also unavailable on that account.

Finally, I followed the approach suggested by the tutorial's authors and used a standard Gmail account. This time, the process went smoothly, and I was able to complete the setup.

Experience (Before 25/03)

To be perfectly honest, I take pride in avoiding the command line whenever possible. However, after this week's experience, I am slightly more inclined to agree that using Git via the command line is considerably more practical and efficient than using the VS Code UI.

Even so, I will continue to avoid the command line where I can, simply because finding workarounds is more amusing and challenging! :D

Experience (On 25/03)

While trying to follow Tutorial 5 on my own, I didn't notice that I should have also read Tutorial 6. As a result, I wasted some time trying to figure out how to send patches with my USP email, even though there was a tutorial specifically for that.

On the day of the tutorial, since I had already finished Tutorial 5, I mainly focused on Tutorial 6. There, I faced some of the simplest yet most frustrating issues yet. Because I was a bit distracted, I first tried to set up the Docker image responsible for sending emails before configuring the email container. This caused my container to initialize without any configuration, leading me to waste an hour and a half trying to figure out what the following error meant:

Unable to initialize SMTP properly. Check config and use --smtp-debug. VALUES: server=127.0.0.1 encryption=tls hello=outlook.com port=2587 at /usr/lib/git-core/git-send-email line 1655.

In the end, all I needed to do was rebuild my container with the correct information already inserted. Even so, since I was the first one to face this problem, I was able to help other students who encountered the same issue, so it was a fun experience by the end of the day.
