A very complicated simple issue

Introduction

This week we worked on a KDE Discover issue about adding a Flatpak source that was already there. It looked like a tiny problem at first, but it ended up eating a surprising amount of time because we kept trying different ideas before landing on the real cause.

The funny part is that this bug bothered me a bit, because I used to have real trouble adding sources when I was trying to download NVIDIA drivers on Debian. I do not have that exact problem anymore now that I use Kubuntu, but I still remember how annoying that kind of flow can be, so the bug made sense to me right away.

The breakthrough came when we checked Discover's logs while trying to add a duplicate source. (You may see that the code that does that is right below our new code) That is when we noticed the warning was already there in the backend, and we also managed to reproduce the issue again after getting a little more comfortable with KDE Builder. 

qCWarning(LIBDISCOVER_BACKEND_FLATPAK_LOG) << "Source" << resource->flatpakName() << "already exists in"
                                                << flatpak_installation_get_path(preferredInstallation());

The Patch itself

After chasing several dead ends, we realized the fix was much simpler than expected: just add one line to an already existing function so Discover could show the user a visible message instead of only writing to the log. 

@@
 if (g_autoptr(FlatpakRemote) remote =
     flatpak_installation_get_remote_by_name(preferredInstallation(), resource->flatpakName().toUtf8().constData(), cancellable, nullptr)) {
+    Q_EMIT passiveMessage(i18n("Source '%1' already exists", resource->flatpakName()));
     qCWarning(LIBDISCOVER_BACKEND_FLATPAK_LOG) << "Source" << resource->flatpakName() << "already exists in"
                                                << flatpak_installation_get_path(preferredInstallation());
     return nullptr;
 }

The issue description in KDE Bug 521044 matched what we saw in practice: Discover did not provide feedback when the repository was already there. The merge request adds that feedback directly in FlatpakBackend.cpp, which is enough to make the duplicate-source path visible to the user.

So even though this week took several detours, the final result was a surprisingly small change that came from paying attention to the logs and being patient while reproducing the bug.
