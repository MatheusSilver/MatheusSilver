Adjusting the Previous Patch to Kernel Standards

Introduction

Despite the strike that started at IME-USP, we still developed our patch for the Linux kernel. The development diary from the previous week can be found through this link.

One week after that post, we received several comments from Jonathan Cameron, Andy Shevchenko, and David Lechner regarding style, code conventions, and, most importantly, a design decision that could potentially improve performance while maintaining readability. We will detail those changes below.

Changes Requested

After v1 was sent, Andy gave one highly valuable suggestion related to the way we were storing data.

Previously, we thought about using an array of structs and linearly searching through it to find whether the register existed or not. However, Andy suggested using an array of values directly, which would allow us to check in constant time whether a conversion existed or not. Below is the previous code and the new code:

The previous suggestion led us to send a third version of the patch. This version was also reviewed by Marcelo Schmitt, who made us notice a small typo in the names of the patch developers, which would have been funny if it had gone to production with a wrong name.

Another suggestion Marcelo and Jonathan sent to us was related to how we were looping through the array. Since register 0 is not used in the conversion, they suggested starting the loop from 1 and, for readability, naming the starting value TSL2591_PRST_ALS_INT_CYCLE_ANY.

As such, the final modification in our patch is shown below:

Previous Code: 

static int tsl2591_persist_lit_to_cycle(const u8 als_persist)
{
	int i;

	for (i = 0; i < ARRAY_SIZE(tsl2591_persist_table); i++) {
		if (als_persist == tsl2591_persist_table[i])
			return i;
 	}

	return -EINVAL;
}

New Code (Marcelo and Jonathan's suggestion)

I was actually happy that they suggested this since, after using C87 with Professor Ernesto Goldberg, I started thinking that this "need" to declare int i before the loop was really ugly. Luckily, the kernel maintainers agree with that. :D 

static int tsl2591_persist_lit_to_cycle(const u8 als_persist)
{
    for (unsigned int i = TSL2591_PRST_ALS_INT_CYCLE_ANY;
         i < ARRAY_SIZE(tsl2591_persist_table);
         i++) {
        if (als_persist == tsl2591_persist_table[i])
            return i;
    }

	return -EINVAL;
}

After those small changes, the patch was finally accepted and is now on the testing branch.
