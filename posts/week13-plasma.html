Setting up for a large project

Introduction

This week we started working on a new project inside the KDE ecosystem, and the first thing we learned is that KDE is much bigger than it looks from the outside. The work item we picked was about adding gaming mice features to the Mouse KCM, with the general goal of bringing support for button remapping, device grouping, illustrations, and optional libratbag integration into Plasma settings.

At first the roadmap looked simple, but it quickly became clear that working on KDE is not just about writing code. You also need to understand where each piece lives, how the different components connect, and when the right move is to ask for help instead of forcing a guess.

The roadmap

The roadmap was simple to describe and hard to execute: improve gaming mouse support in KDE by grouping devices better, handling button mapping, and showing the right UI in Plasma. With Farid's help, we also found that the first step had already been solved in 32c696b45ee661083041aedcd056f5b9ab8e7256. That gave us a clear base for the rest of the work.

We then asked for help in KDE's Matrix community, where Nicolas Fella answered our question and pointed us in the right direction for the second step.

The hard part

We first looked in KWin, but the real work was in plasma-desktop. Then the build problem started: Plasma has a lot of dependencies, and several of them did not work well on my Kubuntu 24.04 setup. I spent almost three days just trying to get a local build that I could test.

Getting unstuck

After that I asked Farid for help again, and he introduced us to the Brazilian KDE community. They suggested using Distrobox with Fedora 42, which made plasma-desktop much easier to compile and test.

I still hate Fedora, but I have to admit it is useful, and its package manager is actually really cool. Once we switched to that setup, we finally managed to finish the second part of the roadmap.

For reference, we also wrote a small setup script for building plasma-desktop inside Distrobox. 

distrobox-create \
  --name kde-dev \
  --image registry.fedoraproject.org/fedora:42

distrobox enter kde-dev

sudo dnf upgrade --refresh

sudo dnf install -y \
    git \
    curl \
    wget \
    vim \
    gcc gcc-c++ \
    make \
    cmake \
    ninja-build \
    meson \
    pkgconf-pkg-config \
    python3 \
    python3-pip \
    python3-setuptools \
    python3-wheel \
    openssh-clients

sudo dnf install -y kdesrc-build

kdesrc-build --initial-setup

sudo dnf groupinstall -y "Development Tools"

sudo dnf builddep -y \
    plasma-desktop \
    plasma-workspace \
    kwin

sudo dnf install -y \
    mdbook \
    libblake3-devel \
    bash-completion-devel

kdesrc-build plasma-desktop

Note: after running kdesrc-build --initial-setup, you may need to edit ~/.config/kdesrc-buildrc and adjust the source-dir parameter to the directory where you keep your repositories, for example ~/repos. This is especially important if you already have a local clone of plasma-desktop or other KDE modules.

Conclusion

This week was less about a single patch and more about inding the right project, understanding the roadmap, asking the right people for help.

We still intend to keep contributing to KDE, and our plan is to finish the mice project and probably continue after the class ends as well.
